## 目标与顺序

2026-09-15 用户确认：下一版优先让 Windows 经 SSH 连接 Linux 后完成开发与审阅。按第一阶段连接可靠性、第二阶段开发闭环逐项实施。用户随后确认真实 Linux Host 尚未准备，先完成实现与自动化验证；真实 Windows → SSH → Linux 验收继续开放。

## 第一阶段：连接可靠性

| 项目 | 实施范围 | 验收 |
| --- | --- | --- |
| R1 有界恢复与诊断 | 已连接后遇到网络中断，有限次数退避重连；认证、协议、配置和清理错误停止；显示尝试次数、最近错误和处理建议，允许停止后手动再连 | 断网恢复、耗尽、撤销、版本变化、关闭取消、双重断线通知、不重放 mutation 的自动化测试 |
| R2 真实 SSH 验收 | 相同源码构建的 Windows client 与 Linux Host；使用用户指定 SSH alias 和隔离项目 | 配对、对话、关闭重开、网络中断、Host 重启、凭证恢复与撤销、不同会话间 stale command 拒绝 |

R1：源码实现与本地自动化验证完成。R2：等待用户提供已准备好的 Linux Host，不连接无关 SSH 主机，不计为通过。

恢复不变量：Host 的 Kernel 是唯一状态源；只有新事件流和快照准备好后才开放命令；失效连接立即停止提交；未确认写操作不自动重放；设备凭证只在兼容性握手通过后使用；关闭客户端保留配对，显式撤销清除配对。

## 第二阶段：远程开发闭环

按下列顺序分项推进，每项同时落实 shared contract、Host 校验、Windows Main/preload、Renderer capability 与验证。不得仅扩充 allowlist 就宣称功能可用。

1. **R3 远程项目选择**：从 Host 返回有界目录列表，明确远程路径；复用已有 Project 注册与信任校验，不把 Windows 路径当作 Linux 路径。覆盖无权限目录、符号链接、取消、重复注册和导航竞态。
2. **R4 文件与 diff 审阅**：优先复用 Git read contract 与现有面板，文件读取限制在已授权项目内；绑定项目、仓库和状态身份，覆盖二进制、大文件、路径越界与迟到响应。
3. **R5 附件上传**：Windows 原生选择文件，Host 接收有界内容并生成远端附件引用；明确大小限制、会话绑定和临时文件清理。覆盖中断、重复提交、取消、中文空格路径及禁止客户端提交任意 Host 路径。
4. **R6 交互补齐**：接通 Host 已有 Ask、扩展对话框与实际需要的授权交互。绑定原会话与请求身份；覆盖过期、重复回应、断线与撤销，不新建通用命令透传。
5. **R7 必要 Git 操作**：复用既有状态、暂存、取消暂存和提交服务；保留信任、仓库队列及 snapshot 校验。覆盖混合修改、冲突、过期状态和结果不确定；不自动提交或推送。

R3：源码实现与本地自动化验证完成，真实 SSH 主机验收待进行。R4：源码实现与本地自动化验证完成，包含 Git 只读传输、Changes/History 与当前变更文件的有界全文阅读；真实 SSH 验收仍待进行。R5：源码实现与本地自动化验证完成，真实 Windows 选择器→SSH→Linux 验收待进行。R6：源码实现与本地自动化验证完成，包含既有 Ask 验证、已适配扩展命令入口及对话框回应；真实 SSH 验收待进行。R7：源码实现与本地自动化验证完成，包含暂存、取消暂存、普通提交、冲突拒绝与结果未确认处理；真实 SSH 验收待进行。开发闭环的完成标准是在 Windows 上选项目、发任务、处理交互、审阅修改并提交，且在真实 SSH 主机上取得证据。

## 第五阶段：多设备配对（R12，实施中）

2026-09-17 代码核对：Desktop Host 与 Web Remote 当前复用单记录 `RemoteDeviceStore`；Desktop Gateway 配对会替换记录并关闭现有控制连接，无凭证握手只返回一个 `pairingId`。Gateway 已对另一控制连接返回 409，因此不能只把存储改为数组就宣称多设备可用。

1. **多设备记录及迁移**：为 Desktop 的 `.desktop-device` 引入有界设备集合，保留旧记录的认证哈希和有效期，原子迁移并在重启后恢复。新设备配对不得替换已有设备；容量耗尽明确失败。Web Remote 的独立单设备文件及协议保持原语义。正式接入迁移前补充发行版与数据格式兼容检查，回退不能先选中一个无法读取当前配对文件的旧版本。
2. **先核对再发送凭证**：升级 Desktop 协议，明确客户端如何在无凭证阶段核对自己的公开配对身份。多个配对共存时仍不得把凭证发送到不匹配的 Host；旧协议、被撤销或过期的设备明确停止连接，不清除其他设备。
3. **按设备撤销与控制连接归属**：Host 能列出并逐个撤销已配对设备，客户端 logout 只撤销自身。控制连接同时绑定设备身份和 controller ID；另一已配对设备不能借用控制编号提交命令。撤销未控制的设备不关闭当前控制连接，撤销当前设备使其事件流和在途操作失效。
4. **控制权沿用现有边界**：本阶段支持多台设备保留配对、轮流连接。现有控制连接未退出时，新设备仍收到明确的占用错误；不自动抢占或反复重连。并发多端编辑不作为“多设备配对已完成”的隐含承诺，也不通过增加第二 Kernel 实现。
5. **验证与交付**：覆盖旧数据迁移、重启、设备上限、双设备独立配对/过期/撤销、控制连接归属、旧请求拒绝、持久化失败，以及单设备现有回归。之后接通 Host 的设备管理入口并进行完整界面和 Windows 本地凭证验证；真实 SSH 验收仍使用用户指定主机。

R12 存储阶段已实现独立的版本 2 集合及版本 1 迁移，最多 8 个设备；共同私有文件读写入口已供原单设备存储使用。新集合暂未接入 Main/Gateway，正式协议仍为版本 2；握手、多设备授权/撤销、管理入口及数据格式回退兼容检查继续实施，不将本阶段计为多设备功能完成。

2026-09-29 R12 本地接入完成（D-101，接口见 [R12 共享接口](r12-shared-interfaces.md)）：Main/Gateway 使用版本 2 集合，Desktop 协议升为 3；无凭证身份核对、逐台撤销与设备列表、设备与 controller 双重绑定、被占用时不抢占不重连、客户端只撤销自身，以及 Windows 计算机名作为设备名称均已接通，`deviceStoreVersions` 为 `[1, 2]`。自动化覆盖真实 HTTP/SSE Gateway 与真实浏览器界面；Windows 原生 Credential Manager 与真实 Windows→SSH→Linux 验收仍按重启计划第二、三轮开放。
